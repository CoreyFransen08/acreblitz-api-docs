---
title: "Migrate to V2"
description: "Move your integration to the supported V2 API"
---

V1 is deprecated and its endpoints are no longer documented. Use `https://esa.acreblitz.com` with the `/api/v2` prefix. Update your request and response handling to the V2 contracts below.

| Topic | V2 behavior |
|---|---|
| Host and paths | Use `https://esa.acreblitz.com/api/v2/...`. |
| Single check | Returns an assessment in the same HTTP response. |
| Bulk checks | Submit 1–100 fields. Confirmed no-ESA jobs return all results immediately; poll other jobs and fetch per-field results. |
| Group identifier | Optional for a single check; required at the top level for bulk. |
| Products and crops | Bulk defaults may be replaced per field; arrays are replaced, not merged. |
| Pest inputs | Each product needs a product pest list or an inherited default. |
| Method and droplet inputs | V2 validates supported categories; arbitrary strings are rejected. |
| PULA limitations | Still returned per product under `products[].pulas[].limitations` (`limitation_id`, `code`, `limitation`, `mitigation_options`) with `summary` counts, on single checks, bulk item results, and the drift-buffer recompute. Compliance GETs return them under `compliance.last_assessment.products`. See [product PULA limitations](/v2/api-reference/endpoint/esa-check#product-pula-limitations). |
| Optional details | `include_soil_analysis` and `include_mitigations` return assessment details when available. |
| Errors | JSON `success: false` and `error.code`; validation errors also include issue paths. |
| Portal links | Use returned links unchanged and honor their expiration. Providers can use token or signed-link access. |
| Report lookup | Use your external `provider_field_id`. |

## Roll out in order

1. Set your API base URL to `https://esa.acreblitz.com/api/v2` and use your provider API key.
2. Validate request construction against the [single check](/v2/api-reference/endpoint/esa-check) and [bulk](/v2/api-reference/endpoint/bulk-submit) contracts.
3. Handle `indeterminate` assessments and partial bulk failures before enabling intake.
4. Move each provider/account workflow to V2 and review its results and compliance reports.
5. Remove deprecated requests from your integration.

Use the [API reference](/v2/api-reference/introduction) to choose supported routes. Changing a URL prefix alone does not update the request or response contract.
