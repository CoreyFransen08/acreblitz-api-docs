Download the Runoff compliance report for a provider-owned field.

<ParamField path="provider_field_id" type="string" required>
  Your field identifier from the single check, bulk field entry, or field-processing request.
</ParamField>

<ParamField query="year" type="integer">
  Optional report year, 1900–2200.
</ParamField>

<ParamField query="grower_name" type="string">
  Optional grower name, up to 200 characters. It prints in the report's **Name** field in place of your provider name.
</ParamField>

<ParamField query="farm_name" type="string">
  Optional farm name, up to 200 characters. It prints before the field name, as `Farm / Field`.
</ParamField>

<Note>
  AcreBlitz does not store `grower_name` or `farm_name`. They apply only to the compliance report from that request. Send them on each download where you want them to appear. Blank values are ignored. A value over 200 characters or with control characters returns `422 INVALID_REQUEST`. URL-encode both values.
</Note>


## Response

A successful request returns **200** with `Content-Type: application/pdf` and an attachment filename. Save the response bytes as a `.pdf` file.

```http 200
Content-Type: application/pdf
Content-Disposition: attachment; filename=mitigation-report.pdf
```

The field must belong to your provider and have an active, unexpired, unarchived portal. An unknown or unavailable field returns 404; an ambiguous field identifier returns 409. Dependent report failures can return 502. The report uses the field's current saved data; the download request does not rerun the ESA check.

The example requests the 2026 report labeled with a grower and farm name.

<RequestExample>

```bash cURL
curl --request GET 'https://esa.acreblitz.com/api/v2/fields/north-field/reports/runoff' \
  --get \
  --data-urlencode 'year=2026' \
  --data-urlencode 'grower_name=Jane Smith' \
  --data-urlencode 'farm_name=North Farm' \
  --header "X-API-Key: $ACREBLITZ_API_KEY" \
  --output runoff-report.pdf
```

</RequestExample>

## Errors

Report errors are `404 FIELD_NOT_FOUND`, `409 DUPLICATE_FIELD`, `502 INVALID_REPORT`, `503 PORTAL_SERVICE_UNCONFIGURED` or `PORTAL_SAS_UNCONFIGURED`, and `PORTAL_REQUEST_FAILED` with HTTP 400, 403, 404, 422, or 502. Error bodies use JSON even though successful responses are PDFs.

All routes can also return [authentication, validation, rate-limit, and dependency errors](/v2/errors#http-error-catalog). Use the [error catalog and examples](/v2/errors) to choose a retry or correction. Keep `X-Request-ID` when present.
