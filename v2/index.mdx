Use V2 to check one pesticide application or submit a group of fields for asynchronous processing. You receive PULA requirements, runoff and drift assessments, and portal links for review.

Base URL: `https://esa.acreblitz.com`. All API routes use the `/api/v2` prefix.

V1 is deprecated. This documentation covers the supported V2 endpoints.

## Interpret an assessment

Read [Understanding compliance determinations](/v2/compliance-determination) for the full runoff and drift workflow, setup violations, status precedence, and when to refresh saved results.

An HTTP 200 response or `success: true` means the request was handled. Read `compliance.status`, `compliance.processing_complete`, and `compliance.issues` before making a decision. A completed calculation can remain `indeterminate` when applicability, weather, or field conditions need review.

| Status | Meaning |
|---|---|
| `met` | Evaluated requirements are met within the assessment's scope. |
| `not_met` | A verified requirement has a shortfall. |
| `not_applicable` | No applicable requirement was established for the verified inputs. |
| `indeterminate` | Evidence, processing, or verification is incomplete. |

An ESA assessment does not grant unrestricted application clearance. Review the product label, returned PULA text, and unresolved conditions.

## Soil reuse and refreshed results

After portal changes, use [get application compliance](/v2/api-reference/endpoint/application-compliance) or [get group compliance](/v2/api-reference/endpoint/group-compliance) to read current runoff scoring, saved requirements, and full drift details. These read-only endpoints use `Cache-Control: no-store`. Their `last_assessment` is historical; retrieval does not produce a new overall compliance verdict.

V2 reuses soil when the field boundary and processing version match. A changed field boundary triggers fresh processing. Background soil enrichment does not rewrite a returned assessment; resubmit the same application to refresh it. Bulk polling responses use `Cache-Control: no-store`. Do not cache job status as a final assessment.
